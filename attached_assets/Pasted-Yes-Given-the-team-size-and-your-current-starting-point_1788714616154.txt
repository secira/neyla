## Engineering rules

6. Do not introduce unnecessary dependencies.
7. Keep the architecture modular.
8. Keep open-source-derived code clearly separated from Neyla proprietary code.
9. Never hard-code API keys or secrets.

12. Maintain clear README and architecture documentation.
13. Do not implement Phase-2 features prematurely.

## Important Replit execution instruction

Do not attempt to implement the entire specification in one operation.

Work in small milestones.

Before modifying code:

1. Inspect the repository.
2. Identify the existing architecture.
3. Identify which functionality already exists.
4. Reuse existing functionality wherever possible.
5. Explain which files/modules will be modified.
6. Implement only the current milestone.
7. Run tests/build.
8. Fix errors.
9. Verify the application.
10. Only then proceed to the next milestone.

At every stage, maintain backward compatibility with existing working functionality.

The first task is NOT to implement features.

The first task is:

> **Audit the existing Neyla codebase and produce a technical architecture report identifying what already works, what can be reused, what must be refactored, and the minimum changes required to implement Phase 1. Do not modify code until the audit is complete.**

## One final recommendation

I would make **Neyla.ai** the application-building product and **Neyla.dev** the developer/integration platform later, exactly along the direction you're considering.

For now:

**Neyla.ai**

> **AI Application Development**

**Neyla.dev**

> **Developer platform / MCP / integrations — coming later**

That gives you a very clean evolution:

**Today**

> "Neyla helps startups and SMEs build real applications with AI."

**Later**

> "Neyla helps businesses connect those applications to their systems."

**Eventually**

> "Neyla provides the execution and governance layer for enterprise AI."

That is a much more achievable journey for a 10-person company than trying to launch the entire enterprise platform now. And the GitHub/code-ownership model is particularly important: current AI application-building workflows already train customers to expect editable code and GitHub portability, so Neyla should make that a foundational promise rather than an afterthought.
